# Architecture Decision Records

ADRs record decisions that shape Sparki's product, architecture, data model, workflow model, or long-term engineering constraints.

## Constitutional Authority

All ADRs inherit from the [Product Constitution](../blueprint/00-product-constitution.md). If an ADR conflicts with the Constitution, the Constitution governs unless a constitutional amendment is accepted.

## Purpose

Preserve decision context so future teams understand why Sparki is built the way it is.

## ADR Format

- Title
- Status
- Date
- Constitutional Reference
- Purpose
- Context
- Decision
- Consequences
- Goals
- Guiding Questions
- Future Sections
- Known Decisions
- Open Questions
- Notes

## Status Values

- `Proposed`
- `Accepted`
- `Superseded`
- `Rejected`

## Notes

ADRs are historical records. If a decision changes, create a new ADR and mark the old one as superseded.
