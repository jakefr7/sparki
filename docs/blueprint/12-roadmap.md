# 12 Roadmap

## Constitutional Authority

This document inherits from the [Product Constitution](./00-product-constitution.md). If it conflicts with the Constitution, the Constitution governs.

## Purpose

Provide a durable structure for roadmap thinking without pretending future sequencing is known before customer evidence exists.

## Goals

- Connect roadmap decisions to company principles.
- Make sequencing tradeoffs explicit.
- Separate discovery, validation, build, launch, and iteration.
- Avoid roadmap sprawl.

## Guiding Questions

- Which workflow unlocks the most customer value earliest?
- What must be true before a clinic can safely run on Sparki?
- Which migration capabilities are required for adoption?
- Which product bets reduce work across many workflows?

## Known Decisions

- The roadmap should be workflow-led, not module-led.
- Migration readiness is part of product readiness.
- AI features should ship only where they remove real operational work.

## Open Questions

- What is the minimum lovable clinic workflow?
- Which customer segment defines the first launch wedge?
- What must Sparki support before replacing a legacy system in a live clinic?

## Notes

The roadmap should be updated as evidence changes. Avoid treating old sequencing as strategy.
