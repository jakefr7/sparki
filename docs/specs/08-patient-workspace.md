# 08 Patient Workspace

## Constitutional Authority

This document inherits from the [Product Constitution](../blueprint/00-product-constitution.md). Patient workspace decisions must preserve constitutional product laws.

## Purpose

Define the patient workspace as the core Sparki product surface.

## Goals

- Establish what the workspace must make visible, actionable, and fast.
- Keep clinical, operational, communication, and financial context connected.
- Define the standards for reducing work inside a patient-centered flow.

## Guiding Questions

- What does a user need to know immediately when opening a patient?
- What actions should be one click away?
- Which work should Sparki prepare before the user asks?
- How should the workspace adapt across roles without becoming fragmented?
