# 10 Migration Engine

## Constitutional Authority

This document inherits from the [Product Constitution](../blueprint/00-product-constitution.md). Migration decisions must preserve constitutional product laws.

## Purpose

Define migration as a core product capability for moving clinics from legacy systems to Sparki with confidence.

## Goals

- Treat migration as a product experience, not a services afterthought.
- Document migration workflows, risks, validation steps, and user-facing expectations.
- Build a shared understanding of data quality and cutover requirements.

## Guiding Questions

- What data must migrate for a clinic to operate safely on Sparki?
- How will clinics verify migrated data?
- What should happen when legacy data is incomplete, inconsistent, or malformed?
- How can migration become a competitive advantage?
