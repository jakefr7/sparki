# Specs

Specs translate Sparki's product philosophy into buildable product and platform direction.

## Constitutional Authority

All specs inherit from the [Product Constitution](../blueprint/00-product-constitution.md). If a spec conflicts with the Constitution, the Constitution governs.

## Purpose

Create a clear bridge between research, product decisions, technical architecture, and implementation work.

## Goals

- Keep product work tied to workflows and customer evidence.
- Separate requirements, decisions, assumptions, and open questions.
- Give engineering and design enough clarity to estimate, sequence, and validate.

## Guiding Questions

- What workflow does this spec improve?
- What patient, client, or clinic context does it preserve?
- What should be faster after this ships?
- What is intentionally out of scope?
